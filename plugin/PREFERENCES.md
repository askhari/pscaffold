# Standing preferences

Durable defaults that every new product inherits. The `kickoff` and `architect`
skills read this file first and **skip any question it already settles**. When a
project deliberately deviates, record the deviation as an ADR in that project —
do not edit this file for one-offs. Promote a deviation here only when it should
become the new default for future products.

## Languages and conventions
- Chat with the user in Spanish or English; **every file is written in English**.
- Client: TypeScript, React Native + Expo (Expo Router, universal: iOS, iPadOS, Android, web).
- Backend: **Go** by default; **Rust** is the supported alternative. Both implement the same contract.
- Languages (Go, Rust, Node) are installed by the developer (Node via fnm, Rust via rustup,
  Go via its own toolchain). Versions are pinned with standard repo files
  (`go.mod`, `rust-toolchain.toml`, `.node-version`, `packageManager`).
- Support tools (just, terraform, tflint, copier, Postgres service, …) come from **Devbox**.
  Never install project tools globally.

## Architecture defaults
- **API-first**: every client talks to the backend only through the HTTP API.
- **Contract-first**: `contract/openapi.yaml` is the source of truth; the TS client and the
  Go server interface are generated from it and CI fails on drift.
- **Offline-first mobile**: SQLite on device, an outbox of mutations, cursor-based pull
  through the API. Data conventions from day one: client-generated UUIDv7 ids, a
  server-assigned `version`, soft deletes (tombstones), last-write-wins unless a domain
  says otherwise. Web starts online-only.
- **Auth inside the API**: email + password (argon2id) and social login (Google, Microsoft,
  Apple) via OIDC ID-token verification; the API issues its own short-lived access token and
  a rotating refresh token. Isolated `auth` module so it can be swapped for an external IdP.
- Database: PostgreSQL (18+, native `uuidv7()`).

## Infrastructure and delivery
- IaC: Terraform. Target: DigitalOcean or an own VPS — chosen per project on cost first,
  then operational effort, then lock-in.
- Environments: start with **dev only**; add `prod` by copying `infra/terraform/envs/dev`.
  Anything real users touch (TestFlight included) counts as prod.
- CI/CD: GitHub Actions. The pull request is the gate; review effort scales with risk.
- Mobile builds and OTA updates: EAS (Build, Submit, Update).
- Monorepo tooling: pnpm workspaces + Turborepo for TypeScript, `just` as the single entry point.

## Working with agents
- `CLAUDE.md` stays short: only what Claude cannot learn from the code.
- Irreversible actions are denied in `.claude/settings.json`; everything reversible is left
  to the model.
- Verification is mechanical: `just check-file`, `just test-affected`, `just verify`, wired to
  hooks that exit 2 on failure.
- Every task ends in a pull request; orchestration happens through Claude Code sessions.
- Model tiers: the manager (`orchestrate`) and the interview skills (`kickoff`, `architect`,
  `spec`) run on the strongest model available. Implementation runs in the `implementer`
  agent on the model `plan` assigns per task — `haiku` for mechanical low-risk changes,
  `sonnet` by default, `opus` for new patterns, security, sync, migrations and high risk.
  A task that fails judgment twice moves one model up.
- Parallel tasks run in git worktrees. Each worktree gets its own databases on the main
  checkout's local Postgres cluster; ports are picked free, never fixed.
